# 20. Места с размером и структура прогулки: места, заходы, переходы, маршруты

Статус: **предложение (D-62), уточнено по сценариям владельца**. Заменяет «место = точка + радиус 60 м» и «прогулка = одно место» и объединяет места, маршруты (`19-routes.md`) и остановки (A-03, A-12) в одну логику.

## 0. Что сделано сейчас и в чём предел

Сделано и проверено (Phase 2, шаги 4–5): место = точка + радиус (по умолчанию 60 м); у прогулки одно место или только тип; карточка «Назвать это место?» (§1); автопредложение A-12 (остановки ≥ 3 мин, кластер из ≥ 3 остановок в ≥ 2 прогулках, дальше 60 м от центра любого сохранённого места).

Пределы:

1. **Размер места не учитывается.** Парк в 33 га и полянка в 40 м описаны одинаково, а алгоритм считает «рядом» 60 м от центра. Внутри большого парка он будет предлагать новые места при каждой повторной остановке.
2. **Остановка = скорость < 0,4 м/с дольше 10 с.** «Кружили по лужку 15 минут, нюхали» остановок почти не даёт.
3. **В прогулке одно место.** Реальный выход: двор → магазин → круг → парк → к маме.
4. **Нет понятия «дом/база».** Прогулка у мамы на 2 часа портит длительность, а обратный путь от мамы начинается не из дома.

Принцип решения: **факты не меняются, структура выводится из них, имена принадлежат человеку.**

```
Слой 1  факты        точки трека, события, ручные паузы                     (не меняются)
Слой 2  структура    заходы (dwell), переходы (leg), поездки, места          (пересчитывается)
Слой 3  смысл        названия мест и маршрутов, база, пометки «внутри»        (решения человека)
```

Слой 2 это чистая функция от (трек, библиотека мест, решения человека). Поменяли форму места, и вся история пересчитывается сама. Нет двух источников правды, поэтому логика не запутывается.

## 1. «Назвать это место?» (реализовано)

Карточка в итоге GPS-прогулки, у которой **нет сохранённого места, но выбран только тип** («Парк», «Луг», …).

1. Позиция: центр самой долгой остановки прогулки, иначе первая точка трека. Нет трека, нет карточки.
2. Кнопки: «Назвать» открывает «Новое место» в этой точке, «Не сейчас» закрывает карточку.
3. Тип в шторке подставлен тот, что выбран перед прогулкой; название необязательно (по умолчанию «Парк», «Парк 2», …; чипы «у дома», «за школой», «у реки», «новое»).
4. Перед сохранением проверка дубликатов (A-24): «Похоже на «Парк у дома». Это то же место?»; «Да, то же» запоминает ввод как синоним и привязывает прогулку к существующему месту.
5. Сохранённое место привязывается к прогулке (`walk.place_id`, `place_kind` очищается).
6. «Не сейчас» не запоминается: решение принимается один раз при открытии итога. Назвать тип можно позже из истории (редактирование прогулки).

Рядом живёт карточка «Вы часто останавливаетесь здесь. Назвать место?» (S14-Auto): не чаще раза в день, с кнопкой «Не предлагать здесь» (запоминается на ячейку ≈ 55 м навсегда); названное место привязывается ко всем прогулкам кластера без места. Две карточки не показываются вместе.

## 3. Места с размером

### 3.1 Типы и размеры по умолчанию

Размеры выбраны по сценариям владельца: парк большой, всё остальное намного меньше.

| Тип | Радиус по умолчанию | Примечание |
|---|---|---|
| Парк | 300 м | заглушка; настоящий размер из контура карты (§3.4); 33,4 га это круг радиусом ≈ 326 м |
| Лес / роща | 250 м | то же, контур из карты |
| Район | 400 м | |
| Набережная | 120 м | |
| Сквер | 80 м | новый тип |
| Полянка / лужок / луг | 50 м | новый тип «Полянка», «Луг» остаётся |
| Аллея | линия, буфер 25 м | новый тип; задаётся по следу прогулки, а не кругом |
| Двор, площадка, тихая улица | 40 м | |
| Магазин, ветклиника, груминг | 40 м | новые «Магазин», «Груминг»; ветклиника уже есть |
| Дом, гости (база) | 40 м | новые «Дом», «Гости»; `is_base` |
| Другое | 60 м | |

Радиус 15–1000 м меняется ползунком с превью на карте. Форма может быть контуром (`shape`), он главнее круга.

### 3.2 Форма, вложенность, принадлежность

- Точка принадлежит месту, если она внутри формы с запасом на точность GPS `min(accuracy, 30 м)`.
- Вложенность район ⊃ парк ⊃ луг (`parent_id`, уже есть). Подходит несколько мест: самое вложенное, при равенстве самое маленькое, затем по `id`.
- Родители подразумеваются: визит на полянку в парке это и визит в парк.
- **Гистерезис.** Вход засчитывается после ≥ 2 мин внутри формы с запасом, выход после ≥ 2 мин снаружи. На границе нет «десяти заходов».

### 3.3 Предложение мест с учётом размера (A-12b)

Вход: **заходы (§4)**.

1. Заход «покрыт», если его центр внутри формы сохранённого места (с родителями). Покрытый заход не даёт нового места верхнего уровня.
2. Непокрытые заходы кластеризуются (DBSCAN); `eps` = `max(40 м, радиус захода / 2)`.
3. Радиус предложенного места: P90 расстояний от центра кластера до заходов + 15 м, не меньше размера по типу.
4. Кластер у края существующего места (в пределах 40 м от границы): вместо нового предлагается «Расширить «Парк 900-летия»?».
5. Внутри существующего места подместо предлагается только при сильных доказательствах: ≥ 5 заходов из ≥ 3 прогулок, разброс ≤ ¼ радиуса родителя, не чаще раза в неделю на родителя.
6. Отказ запоминается.

Так парк в 33 га не засыпает предложениями, а полянка в 50 м остаётся отдельным местом внутри.

### 3.4 Сверка с настоящими картами

Карта **подсказывает**, человек решает; без сети всё работает на круге.

| Этап | Что | Сеть |
|---|---|---|
| А | Круг и ползунок радиуса, размеры по типу | нет |
| Б | «Уточнить по карте»: контур парка/леса/воды из векторной карты OpenFreeMap (слои `park`, `landuse`, `water`), которую приложение уже грузит; «Похоже: парк «900-летия Минска», 33 га. Взять контур?» с превью | да (те же плитки) |
| В | Обводка контура пальцем | нет |

Контур хранится в месте (`shape`), дальше всё работает офлайн. Название из карты только подсказка. Для парков и лесов этап Б должен идти раньше остального, потому что круг для них грубый. Нужен spike **S8**: можно ли у MapLibre RN 11.5 запросить объекты под точкой (`queryRenderedFeatures`) и насколько полны данные по Минску.

## 4. Заходы вместо остановок (A-28, stay points)

**Заход (dwell)**: время, когда человек с собакой остаётся в небольшой области, стоя или бродя внутри.

| Масштаб | Область D | Минимум T | Пример |
|---|---|---|---|
| малый | 40 м | 3 мин | постояли у входа, нюхали куст |
| средний | 120 м | 8 мин | кружили по лужку |
| крупный | 300 м | 15 мин | гуляли в парке |

1. Заход начинается в точке `i`, пока следующие точки в пределах D от `i`, и длится, если набралось ≥ T.
2. Точки с точностью хуже 50 м не участвуют.
3. Вложенные заходы разных масштабов объединяются: хранится самый крупный, мелкие внутри него остаются как «подзаходы» (для §3.3 п. 5).
4. Ручная пауза, пропуск GPS длиннее 30 с и поездки не заходы.
5. A-03 (остановки по скорости) остаётся для темпа и «моментов покоя». Места и маршруты считаются по заходам.

## 5. Структура прогулки

### 5.1 Прогулка от базы до базы

**База** это место, где человек с собакой оказывается внутри надолго: дом, мама, гости. Признак `is_base` (типы «Дом», «Гости»; «Мама» это обычное место типа «Гости»).

Правила разделения записи на прогулки:

1. **Долгий заход в базу (≥ 15 мин) конец прогулки.** Приложение **спрашивает**, не решает само (G-18): «Вы пришли к маме. Завершить прогулку?» с кнопками «Завершить» и «Мы ещё гуляем» (повтор через 30 мин). Короткий заход в базу (< 15 мин: «отдать-забрать») остаётся частью прогулки.
2. **Магазин, ветклиника, груминг не база**: заход есть в хронологии, прогулка не прерывается (R-4, R-9).
3. **Поездка не разделяет прогулку** (R-5): участок со скоростью > 3 м/с дольше 60 с помечается «в дороге» и не входит в дистанцию, темп и длительность ходьбы. Показывается как «в дороге 25 мин».
4. **Следующая прогулка начинается там, где её начали** (после приезда домой рядом с домом). Старт определяется по месту: «Вы здесь: Мама?» (подсказка уже есть). Прогулка от мамы домой отдельная запись «Мама → Дом».
5. **Если запись пережила долгий заход в базу** (забыли завершить, пошли дальше): в итоге предложение «Разделить на две прогулки?» и «Подрезать конец».
6. Все решения можно поправить вручную в деталях прогулки.

### 5.2 Автоматические базы

Базы не нужно заводить вручную:

- **Конец и начало прогулок.** Места, где ≥ 3 прогулки начинались или заканчивались в пределах 60 м, предлагаются как база: «Здесь вы часто начинаете и заканчиваете прогулки. Это ваш дом?» с выбором «Дом» или «Гости».
- **Долгий заход.** Любой заход ≥ 15 мин без движения, где потерян GPS или собака явно в здании: «Вы пробыли здесь 2 часа. Это гости или дом? Завершить прогулку?». Ответ создаёт место-базу в этой точке (радиус 40 м).
- **Гости с ночёвкой** получают базу в первый же раз; три прогулки «из гостей и в гости» это три записи от базы до базы (R-5).

### 5.3 Хронология внутри прогулки

```
Дом (старт) → переход 6 мин → Магазин (заход 7 мин, с собакой)
  → переход 14 мин (круг) → Парк 900-летия (заход 38 мин: полянка 12 мин + аллея 20 мин)
  → переход 9 мин → Дом (конец)
```

| Элемент | Что это | Откуда |
|---|---|---|
| заход | время в области (место из библиотеки или безымянная область) | §4 + §3.2 |
| переход | движение между заходами или между стартом/финишем и заходом | остальное |
| поездка | участок > 3 м/с дольше 60 с | §5.1 п. 3 |
| «внутри» | пометка человека: собаки на улице не было (редко, например у мамы без собаки) | решение человека |

Что это даёт:

- **Визиты в местах считаются по заходам.** Два захода на одну полянку за прогулку это 2 визита, а прогулка с этой полянкой одна. Показываем оба числа.
- **События** уже имеют координаты и получают место по позиции в момент события (`event.place_id`): «Собака» в парке и «Собака» у магазина разведены сами.
- **Маршруты по переходам** (`19-routes.md`): «Дом → Магазин» один путь независимо от того, куда прогулка пошла дальше.
- **Название прогулки выводится само:** «Дом → Магазин → Парк → Дом».
- **Основное место прогулки** то, где заходы заняли больше всего времени, если человек не выбрал своё перед стартом.
- **Ветклиника, груминг, магазин попадают в статистику** (R-9): заходы в них в хронологии, события и время учитываются как обычно.

### 5.4 Хранение

Источник правды прежний (точки, события, решения человека). Производное кэшируется и может быть удалено и пересчитано:

- `walk_visit(walk_id, idx, place_id NULL, lat, lon, radius_m, from_ts, to_ts, scale, indoor)`;
- `walk_leg(walk_id, idx, from_visit, to_visit, length_m, kind 'walk'|'ride', route_id NULL, direction)`;
- решения человека отдельно: `visit_override(walk_id, from_ts, to_ts, place_id | NULL, indoor)` переживают пересчёт.

Пересчёт при завершении прогулки и лениво при изменении формы или добавлении места.

## 6. Маршруты поверх структуры

Подробности в `19-routes.md`. Маршрут это повторяющийся **пеший** переход (или круг), а не прогулка целиком (R-6: поездки на машине не маршруты).

- Переход между двумя местами с похожей геометрией (≥ 80 % точек в 30 м, длина ±25 %) в ≥ 3 прогулках даёт кандидата «Дом → Магазин».
- Прямой и обратный переходы одного коридора это **один маршрут с двумя направлениями**; статистику можно смотреть раздельно и вместе. В каждом проходе показывается число и место остановок по дороге (R-10), поэтому проход «с магазином» и «без» отличается на виду.
- Круг: заход, переход, возврат в тот же заход («вокруг квартала» от дома).
- Название по умолчанию из концов: «{начало} → {конец}», для круга «Круг от {место}».
- Маршрут ничего не меняет в прогулке: подпись, которую выводит приложение и подтверждает человек.

### Что именно реализовано в этапе 2

- **`findStays`** (`packages/core/src/track/stays.ts`): три масштаба (40 м / 3 мин, 120 м / 8 мин, 300 м / 15 мин). Каждая точка (на длинных треках каждая n-я, не больше 1500 центров) рассматривается как возможный центр; для неё берётся самый длинный непрерывный отрезок в радиусе; лучшие отрезки берутся без пересечений. Подход и уход обрезаются (точки дальше 6 м от центра и дальше удвоенного обычного разброса). Крупный заход содержит мелкие внутри (`inner`), копии отбрасываются, частичные пересечения обрезаются до свободной части. Потеря сигнала до 20 мин «склеивается», если человек остался на месте (`gapS`), ручная пауза никогда не склеивается.
- **`clusterStays`** (`packages/core/src/places/stayClusters.ts`): допуск соседства зависит от самих заходов (`max(40 м, 1,5 × больший радиус)`), поэтому визиты в парк (центры далеко) и к двери (центры рядом) работают одним алгоритмом. Нужны ≥ 3 захода из ≥ 2 прогулок; кластер внутри сохранённого места (его радиус, не меньше 60 м) пропускается; меньший кластер внутри большего отбрасывается; радиус предложения охватывает визиты (P90 разброса + 15 м, 40–1000 м).
- **Предложение в итоге прогулки** теперь подставляет радиус и тип по размеру (парк, луг, другое).

### Известные ограничения

- **Очень большие парки по заходам нестабильны.** Собака бродит по разным участкам, центры заходов уезжают на сотни метров, и три визита могут не склеиться. Для парков и лесов главный путь контур из карты (этап 6, spike S8); заходы остаются подсказкой для малых и средних мест.
- Масштаб по умолчанию задан константами (`DEFAULT_STAY_SCALES`); после реальных прогулок значения стоит перепроверить.
- Принадлежность точки месту с гистерезисом 2 мин и «покрытые» заходы по форме считаются на этапе хронологии.
