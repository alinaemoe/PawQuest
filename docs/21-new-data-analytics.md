# 21. Новые данные → аналитика, сравнения, графики, выводы

Со времён первого ТЗ в приложении появились данные, которых не было в плане аналитики (06, 09): погода с состоянием земли, места с размером, заходы, база-к-базе, маршруты, фото, быстрые метки. Здесь записано, **что из них можно честно показать**, как это попадёт в уже спроектированные механизмы (A-07, A-13, A-14, A-26), и что добавить. Решение: D-63. Реализация: Phase 3 (см. roadmap).

Принципы не меняются (06 §6.1, A-00): только факты и сравнения «было / стало», n и интервал рядом с каждым числом, без советов и оценок собаки, «возможно» вместо «потому что».

## 2. Измерения для сравнений (расширение каталога A-14)

К измерениям из 06 §6.4 (контекст, место, время суток, день недели, погода, отвлечение, нагрузка вчера, длительность, предыдущий триггер) добавляются. Все категориальные, границы фиксированы в коде и тестах (как у погоды в D-60).

| Измерение | Значения | Откуда |
|---|---|---|
| Земля | сухо / влажно / мокро / снег / гололёд | производная погоды |
| Давно ли дождь | идёт / до 3 ч / до 24 ч / до 3 суток / дольше | осадки по окнам |
| Температура | ниже −10 / −10…0 / 0…10 / 10…20 / 20…25 / выше 25 | °C на старте |
| Ветер | штиль до 3 м/с / умеренный 3–8 / сильный выше 8 | порывы или ветер |
| Свет | день / сумерки / темно | световой день |
| Воздух | хороший / средний / плохой | AQI с понятной шкалой (D-60) |
| Пыльца | нет / есть | при наличии данных |
| Тип места | 17 типов из D-62, укрупнённо: парк-лес / двор-улицы / вода / городское (магазин, ветклиника, груминг) | `place.category` |
| Размер места | малое (до 60 м) / среднее / большое (от 250 м) | радиус |
| Конкретное место | как есть | `place_id` |
| Тип прогулки | дом → дом / дом → мама / в гостях / по дороге | этап 4 |
| Заход | был заход в магазин / ветклинику / гости | заходы |
| Новизна | первое посещение места / повторное | история мест |
| Маршрут | этот / другой | этап 5 |

Исходы те же, что и раньше (успех навыка, сложный момент на прогулку, реакция ≥ 3, восстановление выше медианы), плюс три **фоновых**, не оценочных: дистанция, время движения, число остановок.

Единица анализа остаётся прежней (D-52): запись с набором измерений. Погоду и место теперь можно подставить в любую запись по её прогулке.

## 3. Какие экраны получат данные

Привязка к уже описанному в 06; новых вкладок нет, только новые блоки.

1. **Walk Details / Summary → «Как обычно».** Строка под фактами: «Дистанция больше обычной в этом месте (n=9: медиана 2,1 км)». Сравнение с «обычным» уже есть в A-26; обычное теперь считается **среди похожих**: тот же тип места и тот же тип прогулки (§4.1).
2. **Insights → Места.** Карточка места: сколько прогулок, медиана времени, события по типам (доли), спокойные и трудные моменты, погода, при которой чаще бывали; график «по неделям» (число прогулок и медиана длительности).
3. **Insights → Поведение.** Pattern cards (A-14) теперь перебирают расширенные измерения; в подписи «найдено среди N проверенных» N вырастет, что и ограничит ложные находки (FDR).
4. **Insights → Обзор → Сравнить (S13-Cmp).** Выбор «сухо против мокро» и «парк против двора»: таблица A, B, разница, n, надёжность. Набор готовых пар (шаблоны) делает сравнение на один тап.
5. **Insights → Здоровье и активность.** Нагрузка по неделям с разбивкой по погоде (сколько прогулок ушло в мокрую землю), температуры в дни с короткими прогулками.
6. **Replay.** Фото на временной шкале и на карте; погода и заходы как подписи к отрезкам.
7. **Недельный итог (A-17).** Одна фраза про самое заметное (шаблон), например «Три прогулки из пяти прошли по мокрой земле — самые короткие».

## 4. Как считать (правила, не формулы алгоритма)

### 4.1 Сравнение «с похожими» (A-26 уточнение)
Прогулка сравнивается только с прогулками **того же типа места и того же типа прогулки**; если таких меньше 5, сравнивать со всеми и написать это («обычных прогулок в таких местах пока мало»). Никогда не сравнивать 8-минутный дворовый выход с 90-минутным парком.

### 4.2 Страты и «сопутствующие» причины
Погода и место связаны (парк чаще по выходным, в сухую погоду). Перед показом карточки «погода → исход» проверяется стратификация: если после разбиения по типу места эффект исчезает, карточка не показывается как «погода», а подаётся как «в парке» (с пометкой «вместе с сухой погодой»). Простое правило: карточка проходит, если знак и размер эффекта сохраняются хотя бы в одной из двух страт «парк-лес» / «двор-улицы» при n ≥ 5.

### 4.3 Множественные сравнения
Новые измерения увеличивают число проверок. FDR 0,2 (A-14) остаётся; N проверенных выводится в подписи. Измерения группируются: «погода» = земля, температура, ветер, свет, воздух: из группы выбирается одна лучшая карточка в день.

### 4.4 Что не делаем
- Не выводим «причину» и не даём совет (G-19): «чаще при мокрой земле», не «из-за дождя».
- Не сравниваем места с n < 5 прогулок; конкретные места попадают в сравнение только после пятой прогулки.
- Не считаем заходы в магазин, ветклинику и груминг в статистику прогулки (D-62), но по ним можно показать «заходов в этом месяце».
- Не показываем фото в статистике; они остаются в Replay и деталях.
- Не усредняем температуры без разбиения (средняя температура сезонов ничего не говорит); только интервалы.
- Маршруты сравниваются только после трёх проходов.

## 5. Графики

| График | Что показывает | Данные | Минимум |
|---|---|---|---|
| Прогулки по неделям | число и суммарное время, цвет по земле (сухо / мокро) | прогулки + погода | 3 недели |
| Длительность и температура | точки прогулок: температура по X, время по Y, тренд (A-09) | прогулки | 15 прогулок |
| Место: неделя за неделей | медиана длительности и событий | прогулки места | 5 прогулок |
| Реакции по типу места | столбики с интервалом Уилсона | события + места | n ≥ 5 в группе |
| Сложные моменты по свету | день / сумерки / темно | события + световой день | n ≥ 5 в группе |
| Время восстановления | после трудных моментов по неделям (A-16) | события | 3 события в неделе |
| Карта заходов | тепловая карта заходов и их длительность | заходы | 10 заходов |

Все графики — столбики или точки с интервалом, без сглаживающих кривых, пока данных мало.

## 6. Как отправлять новые данные в «переработку»

Данные проходят три слоя (09 §9.2). Новые источники добавляются в **первый** слой, остальные не меняются.

1. **Слой фактов** (хранится, не пересчитывается): погода, трек, события, фото, радиус места. Миграции уже есть.
2. **Слой производных** (пересчитывается, версионируется): заходы, хронология, тип прогулки, маршруты, категории погоды, укрупнённые типы места. Каждая производная имеет `algo_version`; при смене порога пересчитываются все прогулки (идемпотентно, в фоне, один раз). Таблица `walk_derived(walk_id, kind, algo_version, json)` — единая точка; нужна миграция при начале Phase 3.
3. **Слой выводов** (pattern cards, сравнения, недельный итог): строится только из производных и фактов; чистые функции в `packages/insights`, как A-13/A-14. Вход — плоский список единиц анализа `{id, dims: Record<string,string|undefined>, outcomes: Record<string,boolean|undefined>}`; собирается одним запросом-сборщиком в `packages/data` (тесты на контракт).

Пересчёт запускается: при открытии вкладки Insights, если `algo_version` устарела; после ручной правки места или разделения прогулки; по кнопке «Пересчитать» в настройках.

## 8. Тесты (как и везде)

- Сценарные: «семь мокрых и пять сухих прогулок, на мокрых больше сложных моментов» даёт карточку; «после стратификации по месту эффект исчез» карточку не даёт.
- Граничные: ровно 4 и 5 прогулок в группе, ровно на границе температуры, прогулка без погоды (измерение не определено, единица не участвует).
- Свойства: порядок прогулок не влияет; добавление нерелевантной прогулки не увеличивает число карточек выше предела; N проверенных равен числу кандидатов с n ≥ 5.
- Фаззинг сборщика на случайных базах.

## 10. Как построен фундамент (Phase 3, шаг 1)

Порядок работы по просьбе владельца: **сначала надёжная основа, потом экраны**. Экранов пока нет; основа проверена тестами и работает на телефоне в фоне.

**Слои** (как в §6, теперь в коде):

| Слой | Где | Что |
|---|---|---|
| Факты | `walk`, `track_point`, `event`, `place`, `weather_snapshot` | не меняются выводами |
| Измерения (чистые функции) | `weather/dimensions.ts`, `insights/dimensions.ts` | погода и прогулка в категории; полосы записаны в тестах, у каждой версия |
| Производные | таблица `walk_derived` (миграция 0011), `data/derived.ts` | `structure` (концы прогулки, заходы, поездки, магазин) и `dims` (все измерения и исходы) |
| Выводы | `data/analysis.ts` + `insights/patterns.ts` | `buildAnalysisUnits`, `walkPatterns` (карточки A-14 по каталогу измерений) |

**Правила надёжности:**
1. **Производное не истина.** Любую строку можно удалить (`clearDerived`), результат совпадёт (тест).
2. **Версия правила** (`DERIVED_VERSIONS`) в каждой строке: поменялась полоса или правило, версия выросла, всё пересчитывается само, пока не пересчитано устаревшее не используется в выводах.
3. **Отпечаток фактов** (`fingerprint`: прогулка, число и последняя точка трека, места, погода, события): изменился факт, пересчитывается только затронутая прогулка (новое место пересчитывает все: места общие).
4. **Одна прогулка одна транзакция.** Сбой в одной прогулке записывается как `error` (прогулка не пробуется снова, пока не изменятся её факты или версия или не попросят `retryErrors`) и не останавливает остальные. Повреждённый JSON это пропуск, не падение.
5. **Порциями.** `refreshDerived(limit)` считает несколько прогулок за раз, возвращает `remaining`; приложение вызывает по 4 прогулки каждые 60 мс после отрисовки (`useDerivedRefresh`) и при каждом изменении данных; прервать можно в любой момент.
6. **Честные исходы.** Прогулка без событий и без законченного итога ничего не говорит о «трудных моментах»: её исходы не определены, она не участвует в этих сравнениях (G-19).
7. **Каталог:** измерения `time_of_day, day_type, duration, place_kind, place_size, walk_type, shop_visit, ride, ground, rain_recency, temp, wind, light, air, pollen, paw_heat`; исходы `hard_moment, success, strong_reaction`.
